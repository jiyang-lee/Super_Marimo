# 브랜치 운영 원칙

이 저장소는 하나만 유지하고, 작업은 브랜치로 분리한 뒤 PR로 `main`에 합친다.

## 브랜치 역할
- `main`: 최종 통합 브랜치
- `backend/*`: 백엔드 작업 브랜치
- `frontend/*`: 프론트엔드 작업 브랜치
- `feature/*`: 짧은 보조 작업이 필요할 때만 사용

## 기본 규칙
- 프론트와 백엔드는 같은 레포에 둔다.
- 백엔드 작업은 `backend/*`에서 한다.
- 프론트 작업은 `frontend/*`에서 한다.
- 서로의 브랜치에 직접 커밋하지 않는다.
- 모든 병합은 PR로만 한다.
- 한 PR에는 한 책임만 넣는다.

## 브랜치 생성 규칙
- 백엔드 작업 시작:
  - `backend/<작업명>`
- 프론트 작업 시작:
  - `frontend/<작업명>`
- 작업명이 길면 짧게 줄이고, 역할이 바로 보이게 쓴다.

## PR 기준
- 제목에 작업 범위가 드러나야 한다.
- 본문에 변경 이유를 적어야 한다.
- 검증 방법을 적어야 한다.
- 남은 이슈가 있으면 적어야 한다.
- 백엔드와 프론트가 섞였으면 분리해서 올린다.

## 운영 순서
1. `main`에서 작업 브랜치를 딴다.
2. 각자 자기 브랜치에서만 작업한다.
3. 테스트와 정리를 마친 뒤 PR을 연다.
4. 리뷰 후 `main`으로 합친다.
5. 다음 작업은 다시 `main` 기준으로 시작한다.

## 주의점
- `main`은 최종 결과물만 모이는 곳이다.
- 브랜치 이름이 역할을 말해줘야 한다.
- 같은 파일을 프론트와 백이 동시에 건드려야 하면 먼저 API 계약을 고정한다.
