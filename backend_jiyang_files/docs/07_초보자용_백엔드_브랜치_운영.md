# 초보자용 백엔드 브랜치 운영

이 문서는 GitHub 초보자가 백엔드 작업을 안전하게 시작하고 끝내는 방법을 정리한 것이다.

## 핵심 규칙
- 백엔드 작업은 항상 `backend/*` 브랜치에서만 한다.
- 기준 브랜치는 항상 `main`이다.
- `main`에는 직접 커밋하지 않는다.
- 한 브랜치에는 한 작업만 넣는다.
- 작업이 끝나면 PR로 `main`에 합친다.

## 가장 단순한 흐름
1. `main` 최신화
2. `backend/*` 브랜치 생성
3. 백엔드 수정
4. 커밋
5. 원격 push
6. PR 생성
7. 리뷰 후 `main` 병합
8. 브랜치 삭제

## 매번 쓰는 명령
```powershell
git checkout main
git pull origin main
git checkout -b backend/<작업명>
```

예시:
```powershell
git checkout -b backend/api-voice-link
```

## 커밋과 push
```powershell
git add .
git commit -m "feat: 백엔드 작업 내용"
git push -u origin backend/<작업명>
```

## PR 만들 때 넣을 것
- 무엇을 바꿨는지
- 왜 바꿨는지
- 어떻게 검증했는지
- 남은 문제는 있는지

## 초보자 안전장치
- 작업하기 전에 `main`으로 돌아온다.
- 브랜치 이름만 봐도 백엔드 작업임이 보여야 한다.
- 헷갈리면 커밋보다 먼저 확인한다.
- 프론트 브랜치와 섞지 않는다.
- 한 번에 하나의 PR만 정리한다.

## 추천 브랜치명
- `backend/api-voice-link`
- `backend/db-init`
- `backend/session-save`
- `backend/health-check`

## 끝낼 때 확인
- 작업한 내용이 `backend/*` 브랜치에만 있는지 확인한다.
- PR이 `main` 대상으로 열렸는지 확인한다.
- 병합 후 브랜치를 지운다.
