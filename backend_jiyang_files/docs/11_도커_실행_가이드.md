# Super_Marimo Docker 실행 가이드

이 문서는 `Super_Marimo` 베타를 Docker로 띄우고 확인하는 방법을 정리한 실행 가이드입니다.

## 0. 실행 순서 요약

1. `docker-compose.yml` + 원하는 overlay 1개를 함께 올립니다.
2. Docker 서비스는 `db-server`, `api-server`, `llm-server`, `voice-server`, `voice-agent` 를 포함합니다.
3. `bridge` 는 Docker가 아니라 Windows host 에서 별도로 실행합니다.
4. `health` 는 프로세스 생존만 보고, `ready` 는 모델 준비 상태를 봅니다.
5. `frontend/beta-dashboard.html` 에서 센서, 이벤트, 세션, TTS 를 한 화면으로 확인합니다.

## 1. 전제

- 저장소 루트: `C:\Projects\_active\Super_Marimo`
- Docker Desktop 설치 완료
- `docker compose` 사용 가능
- 베타 확인용 기본 순서는 `mock -> cpu -> gpu -> dev` 입니다.

## 2. compose 파일 역할

| 파일 | 역할 | 주 사용처 |
|---|---|---|
| `docker-compose.yml` | 공통 베이스 | 모든 모드의 공통 설정 |
| `docker-compose.mock.yml` | 모의 데이터 중심 | 빠른 기능 확인 |
| `docker-compose.cpu.yml` | CPU 실행 | GPU 없이 LLM / Voice 확인 |
| `docker-compose.gpu.yml` | GPU 실행 | 실제 모델 실행 |
| `docker-compose.dev.yml` | 개발용 overlay | live reload / 개발 편의 |

## 4. 중지 명령

실행한 모드에 맞는 파일 조합으로 `down` 을 사용합니다.

```powershell
docker compose -f docker-compose.yml -f docker-compose.mock.yml down
docker compose -f docker-compose.yml -f docker-compose.cpu.yml down
docker compose -f docker-compose.yml -f docker-compose.gpu.yml down
docker compose -f docker-compose.yml -f docker-compose.dev.yml down
```

## 6. health / ready 확인

```powershell
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod http://localhost:8001/health
Invoke-RestMethod http://localhost:8001/ready
Invoke-RestMethod http://localhost:8002/health
Invoke-RestMethod http://localhost:8002/ready
Invoke-RestMethod http://localhost:8003/health
```

### 확인 포인트

- `api-server` 는 `health` 만 확인하면 됩니다.
- `llm-server` 는 `health` 와 `ready` 를 분리해서 봅니다.
- `voice-server` 도 `health` 와 `ready` 를 분리해서 봅니다.
- `voice-agent` 는 `health` 로 event poller 상태와 API 연결을 확인합니다.

## 7. 실행 순서 추천

### 1) mock 으로 빠른 확인

```powershell
docker compose -f docker-compose.yml -f docker-compose.mock.yml up -d
```

확인:

```powershell
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod http://localhost:8003/health
```

### 2) 센서 / 이벤트 확인

```powershell
Invoke-RestMethod -Method POST -Uri http://localhost:8000/sensor/realtime-ingest -ContentType "application/json" -Body '{"light":200,"distance":40}'
Invoke-RestMethod -Method POST -Uri http://localhost:8000/events/wakeword -ContentType "application/json" -Body '{"event_type":"wakeword","device_id":"rp2040","trigger_source":"manual","generated_text":"wakeword detected","played":false,"status":"pending","meta":{}}'
```

### 3) voice / session 확인

```powershell
Invoke-RestMethod -Method POST -Uri http://localhost:8000/voice/ask -ContentType "application/json" -Body '{"text":"안녕","use_sensor_context":false}'
Invoke-RestMethod http://localhost:8000/sessions
```

### 4) gpu 모드로 실제 모델 확인

```powershell
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d
```

그 다음:

```powershell
Invoke-RestMethod http://localhost:8001/ready
Invoke-RestMethod http://localhost:8002/ready
```

## 8. 브리지 실행

브리지는 Windows host 에서 별도로 실행합니다.

```powershell
cd C:\Projects\_active\Super_Marimo
python -m bridge.main --port COM4
```

필요하면 디버그 출력 디렉터리를 추가합니다.

```powershell
python -m bridge.main --port COM4 --debug-dir bridge\captures
```

## 10. 자주 쓰는 문제 해결

- `docker compose` 가 안 되면 Docker Desktop 실행 여부를 먼저 확인합니다.
- `ready` 가 503 이면 모델 로딩 중이거나 GPU / CPU 모드가 맞지 않은 것입니다.
- 이벤트가 중복으로 쌓이면 `voice-agent` 로그와 `device_event_log.status` 를 함께 확인합니다.
- TTS 재생이 안 되면 `voice-server` 로그와 `bridge` 재생 로그를 같이 봅니다.
