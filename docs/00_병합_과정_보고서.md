# 병합 과정 보고서

작성일: 2026-05-18

## 1. 개요
이번 병합 작업은 `voice-agent`, `api-server`, `db-server`, `llm-server`, `voice-server`를 하나의 로컬 스택으로 다시 묶고, 실제 대화 흐름이 DB 저장까지 이어지도록 정리하는 데 목적이 있었다.

핵심 방향은 다음과 같다.
- `voice-agent`는 오케스트레이션 계층으로 유지
- `api-server`는 세션과 상호작용 로그 저장 책임 유지
- `db-server`는 PostgreSQL 영속 저장소로 유지
- `llm-server`, `voice-server`는 로컬 부트스트랩이 가능하도록 mock 기준으로 먼저 안정화

## 2. 병합 내용
### 2-1. `voice-agent` 재연결
기존 `voice-agent`는 `voice-server`와 `llm-server`만 직접 묶는 형태였는데, 이번 병합에서는 `api-server /voice/ask`를 먼저 호출하도록 바꿨다.

변경 결과:
- 질의 입력 수신
- `api-server /voice/ask` 호출
- 세션 ID 로컬 저장
- 필요 시 `voice-server /tts`로 음성 생성
- health 응답에서 `api-server`, `voice-server`, `llm-server` 상태를 함께 확인

### 2-2. compose 연결 정리
`docker-compose.yml`에서 다음 연결을 맞췄다.
- `voice-agent`가 `API_SERVER_URL`을 받도록 추가
- `voice-agent`가 `api-server`, `llm-server` health 이후에 시작되도록 조정
- `api-server`에 healthcheck 추가
- 로컬 부트스트랩 안정성을 위해 `llm-server`, `voice-server`는 `MOCK_MODE=true` 기본값으로 정리

### 2-3. 문서 정합성 정리
기존 README들은 현재 구조와 문장 톤이 맞지 않는 부분이 있어서 같이 정리했다.
- 루트 `README.md`를 현재 스택 기준으로 재작성
- `voice_agent/README.md`에 실제 호출 흐름 반영
- `api_server/README.md`, `db_server/README.md`를 현재 책임 분리 기준으로 정리

### 2-4. 검증용 테스트 추가
`voice_agent/tests/test_main.py`를 추가해서 다음을 확인할 수 있게 했다.
- `/health`가 downstream 상태를 함께 반환하는지
- `/ask`가 `api-server`를 경유하는지
- 세션 ID 저장이 유지되는지

## 3. 실제 검증 결과
로컬 Docker 기준으로 아래 흐름을 확인했다.

실행:
```powershell
docker compose up -d --build db-server api-server llm-server voice-server voice-agent
```

확인 결과:
- `db-server` 정상 기동
- `api-server` 정상 기동 및 DB health 통과
- `llm-server` 정상 기동
- `voice-server` 정상 기동
- `voice-agent` 정상 기동

API 검증:
- `http://localhost:8000/health`
- `http://localhost:8001/health`
- `http://localhost:8002/health`
- `http://localhost:8003/health`

추가 확인:
- `voice-agent /ask` 호출 후 `api-server /sessions`에 세션이 저장됨
- PostgreSQL에 `session`, `session_message`, `sensor_readings`, `interaction_log` 테이블이 존재함

## 4. 현재 상태
현재 기준 동작 흐름은 아래와 같다.

1. `voice-agent`가 질의를 받는다.
2. `voice-agent`가 `api-server /voice/ask`를 호출한다.
3. `api-server`가 응답 생성과 DB 저장을 처리한다.
4. `voice-agent`가 필요하면 `voice-server /tts`를 호출한다.
5. `db-server`에 세션과 대화 로그가 남는다.

## 5. 정리
이번 병합의 핵심은 "대화 오케스트레이션"과 "영속 저장"의 책임을 다시 연결한 것이다.

정리된 기준은 다음과 같다.
- 대화 흐름의 시작점은 `voice-agent`
- 저장 책임은 `api-server`
- 저장소는 `db-server`
- STT/TTS는 `voice-server`
- 응답 생성은 `llm-server`
