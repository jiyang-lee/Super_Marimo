# 프로젝트 규칙

## 1. 프로젝트 한 줄 설명
이 프로젝트는 `음성+DB+LLM 통합` 로컬 스택이다.

## 2. 핵심 원칙
- 모든 설명과 문서는 한국어로 작성한다.
- 큰 기능 추가나 구조 수정이 생기면 반드시 보고서를 남긴다.
- 결정이 필요한 지점은 임의로 넘기지 말고 되묻는다.
- 코드는 항상 간결하고 심플하게 유지한다.

## 3. 작업 원칙
- 먼저 현재 파일과 실제 동작을 확인한 뒤 수정한다.
- 문서와 코드가 어긋나면 같은 작업 안에서 같이 맞춘다.
- 작은 변경으로 끝낼 수 있으면 큰 구조 변경보다 작은 변경을 우선한다.
- 검증 가능한 작업은 실제 명령과 결과로 확인한다.

## 4. 금지 사항
- 인코딩이 깨진 상태로 두지 않는다.
- 마음대로 삭제하지 않는다.
- 사용자 의도 없이 범위를 넓혀 기능을 추가하지 않는다.
- 확인되지 않은 상태를 성공처럼 말하지 않는다.

## 5. 되물어야 하는 경우
- 문서 제목이나 형식을 정해야 할 때
- 삭제, 이동, 대규모 변경이 필요한데 범위가 불명확할 때
- 여러 선택지가 있고 결과가 달라질 때
- 보고서의 상세 수준이나 대상 독자가 다를 때

## 6. 우선순위
1. 한국어 유지
2. 인코딩 유지
3. 삭제 금지
4. 간결한 구현
5. 변경 시 보고서 남기기
