# GitHub 운영 규칙

## 1. 기본 원칙
- 저장소는 하나로 유지한다.
- 최종 통합 브랜치는 `main`이다.
- 작업은 브랜치로 나눠서 하고, 병합은 PR로만 한다.
- 프론트와 백엔드는 같은 레포에 두되 브랜치로 분리한다.

## 2. 브랜치 규칙
- `main`: 최종 통합 브랜치
- `backend/*`: 백엔드 작업 브랜치
- `frontend/*`: 프론트엔드 작업 브랜치
- `feature/*`: 필요할 때 쓰는 세부 작업 브랜치

## 3. 작업 책임
- 백엔드 작업은 `backend/*`에서 진행한다.
- 프론트엔드 작업은 `frontend/*`에서 진행한다.
- 서로의 브랜치에 직접 커밋하지 않는다.
- 한 PR에는 한 책임만 넣는다.

## 4. 병합 기준
- 코드가 돌아가야 한다.
- 변경 이유가 PR 설명에 있어야 한다.
- 검증 방법이 PR에 적혀 있어야 한다.
- 문서나 API 계약이 바뀌면 같이 갱신한다.

## 5. PR 작성 기준
- 제목은 작업 범위가 보이게 쓴다.
- 본문에는 다음을 넣는다.
  - 무엇을 바꿨는지
  - 어떻게 검증했는지
  - 남은 과제가 있는지
- 프론트/백엔드 혼합 변경은 가능하면 분리한다.

## 6. 협업 방식
- 팀원은 `frontend/*` 브랜치에서 새 프론트를 만든다.
- 백엔드는 내가 관리한다.
- 최종 결과는 `main`에 모은다.
- `main`에 들어가기 전에는 PR 기준으로 리뷰하고 검증한다.
