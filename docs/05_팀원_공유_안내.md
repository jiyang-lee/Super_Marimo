# 팀원 공유 안내

이 문서는 팀원에게 그대로 전달해도 되는 작업 방식이다.

## 전달 문구
```text
이 레포는 하나의 저장소로 같이 관리하고,
나는 backend/* 브랜치에서 백엔드를, 너는 frontend/* 브랜치에서 프론트를 작업해줘.

main은 최종 통합용이라 직접 커밋하지 말고,
작업이 끝나면 PR로 main에 합치는 방식으로 가자.

브랜치 이름은 frontend/작업명 형식으로 부탁하고,
한 PR에는 한 책임만 넣어줘.
API가 바뀌는 경우엔 먼저 백엔드 계약을 맞춘 뒤 프론트 작업을 이어가면 돼.
```

## 팀원 작업 방식
- 레포를 clone 한다.
- `main` 기준으로 자기 브랜치를 만든다.
- 프론트 작업은 `frontend/*`에서만 한다.
- 커밋은 자기 브랜치에만 한다.
- PR로 `main`에 올린다.

## 내가 보는 기준
- 브랜치 이름이 프론트 작업임을 보여야 한다.
- PR에 검증 방법이 있어야 한다.
- 백엔드와 충돌하는 변경이면 먼저 이야기한다.
- 기존 프론트 구현을 이어서 고치는 방식이 아니라, 새 구조로 만들어도 된다.

## 예시 브랜치명
- `frontend/login-page`
- `frontend/main-layout`
- `frontend/dashboard-redesign`
