# 베타 전환 운영 규칙

이 저장소는 베타 서비스로 가기 위한 백엔드 중심 작업을 진행한다.

## 1. 목표
- 기존 서버를 버리지 않고 역할을 다시 정리한다.
- 베타 핵심 흐름은 `wakeword -> manual-test -> sensor-warning` 이지만, 이번 구현은 `wakeword`와 `manual-test`만 먼저 완성한다.
- 프론트는 운영용 상태 UI로 최소만 유지한다.

## 2. 서버 역할
- `api-server`
  - 세션 저장
  - 이벤트 로그 저장
  - 쿨다운/자동응답 정책
- `voice-server`
  - STT
  - TTS
- `llm-server`
  - 답변 생성
- `voice-agent`
  - 서버 사이 오케스트레이션

## 3. 이벤트 규칙
- `wakeword`는 1차 트리거다.
- `manual-test`는 장치 없이 검증하는 수동 이벤트다.
- `sensor-warning`는 임계치가 사용자 결정사항이므로 보류한다.
- 대화 로그와 디바이스 이벤트 로그는 구분한다.

## 4. Git / GitHub 규칙
- 저장소는 하나만 유지한다.
- 작업은 브랜치로 나눈다.
- `main`은 최종 통합용이다.
- 백엔드는 `backend/*`
- 프론트는 `frontend/*`
- PR은 한 작업만 담는다.
- 병합 후 브랜치는 정리한다.

## 5. 작업 종료 규칙
- 큰 기능이 끝나면 보고서를 남긴다.
- 보고서는 한국어로 쓴다.
- 서버 구조나 DB 구조가 바뀐 보고서는 수정된 다이어그램을 최상단에 둔다.
- 다이어그램, 변경 내용, 검증 결과, 남은 이슈를 모두 넣는다.
