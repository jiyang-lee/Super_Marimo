# 커밋 이메일/신원 문제 설명

## 1. 목적
이 문서는 일부 커밋이 GitHub 컨트리뷰터(기여자)로 제대로 집계되지 않은 이유를 설명한다.

목적은 히스토리를 다시 쓰는 것이 아니라, 왜 같은 사람의 커밋이 여러 신원으로 나뉘어
남았는지, 그리고 일부가 GitHub 프로필에 연결되지 않았는지를 오해 없이 기록하는 것이다.

## 2. 현상
`git shortlog -sne` 기준으로 한 명의 작업자가 서로 다른 신원으로 나뉘어 기록되어 있다.

| 표시 이름 | 이메일 | 커밋 수 | GitHub 연결 |
| --- | --- | --- | --- |
| namly | govl3773@gmil.com | 13 | ❌ 미연결 (오타) |
| govl3773-spe | govl3773@gmil.com | 3 | ❌ 미연결 (오타) |
| govl3773-spe | govl3773@gmail.com | 6 | ✅ 정상 연결 |

즉 본인 커밋 22개 중 16개가 GitHub 계정에 연결되지 않았다.

## 3. 원인
### 3-1. 이메일 오타
- 로컬 Git 설정(`user.email`)이 `govl3773@gmail.com`이 아니라 `govl3773@gmil.com`으로
  되어 있었다. (`gmail` → `gmil`)
- GitHub은 커밋의 author 이메일이 **계정에 인증(verified)된 이메일**과 일치할 때만
  그 커밋을 해당 계정에 연결한다.
- `gmil.com`은 실제로 존재하지 않는(본인 소유가 아닌) 주소라 인증할 수 없으므로,
  이 이메일로 만든 커밋은 GitHub 프로필/기여 그래프에 잡히지 않는다.

### 3-2. 신원이 꼬인 이유
- 작업 환경마다 `user.name`/`user.email` 설정이 달라, 같은 사람이
  `namly`와 `govl3773-spe`라는 두 이름, 그리고 오타 이메일과 정상 이메일 두 개로
  나뉘어 커밋되었다.
- Git은 커밋 author를 "이름 + 이메일" 문자열로 그대로 기록하므로, 설정이 일관되지 않으면
  동일인이 여러 기여자처럼 분리되어 남는다.

## 4. 영향
- 코드/작업 내용 자체에는 아무 문제가 없다. 파일과 결과물은 정상이다.
- 다만 GitHub 컨트리뷰터 목록과 기여 그래프에서 오타 이메일 커밋(16개)이
  본인 계정으로 집계되지 않아, 실제 기여보다 적게 보인다.

## 5. 해결 방향 (안전한 방법)
팀원 저장소와 기존 히스토리를 깨지 않기 위해, 과거 커밋을 강제로 재작성(force-push)하지
않는다. 대신 앞으로의 신원을 바로잡고 새 커밋으로 기여를 이어간다.

1. 로컬 Git 신원을 올바르게 고정한다.
   - `git config user.name  "govl3773-spe"`
   - `git config user.email "govl3773@gmail.com"`
   - (이 변경은 앞으로 만들 커밋의 author 정보만 바꾸며, 기존 파일·커밋·히스토리는
     건드리지 않는다.)
2. GitHub Settings → Emails 에서 `govl3773@gmail.com` 이 Verified 상태인지 확인한다.
3. 이후 본인 신원으로 커밋·push 하면 즉시 컨트리뷰터로 집계된다.

## 6. 참고 / 한계
- 과거 오타 이메일 커밋(16개)은 위 방법으로는 소급 복구되지 않는다.
- 소급 복구하려면 Git 히스토리 재작성과 force-push가 필요한데, 이는 다른 팀원의 로컬
  저장소를 깨뜨리므로 본 프로젝트에서는 수행하지 않는다.
- 따라서 평가/발표 기준은 "GitHub 그래프 숫자"가 아니라 "실제 작업 내용과 결과물"로
  보는 것이 정확하다.

## 7. 결론
같은 작업자가 이메일 오타와 설정 불일치로 여러 신원으로 나뉘어 기록되었고, 그중 오타
이메일 커밋은 GitHub 계정에 연결되지 않았다. 앞으로는 신원을 일관되게 맞춰
(`govl3773-spe <govl3773@gmail.com>`) 커밋하며, 과거 기록은 본 문서로 설명을 남기는
방식으로 관리한다.
