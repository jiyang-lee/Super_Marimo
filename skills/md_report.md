# md_report

## 언제 쓰나
- 큰 기능 추가 후 정리 보고서가 필요할 때
- 병합, 연결, 검증 결과를 마크다운으로 남길 때
- 작업 내역을 다른 사람이 바로 읽게 만들 때

## 사용자에게 받을 것
- 보고서 제목
- 대상 프로젝트 또는 폴더
- 핵심 변경 사항
- 검증 결과
- 분량 수준

## 진행 순서
1. 현재 파일과 실제 결과를 확인한다.
2. 변경 전후를 정리한다.
3. 기능, 검증, 남은 과제를 순서대로 쓴다.
4. 한국어 문장으로 마무리한다.

## 출력 기준
- 제목이 먼저 보인다.
- 개요, 변경 내용, 검증 결과, 현재 상태가 보인다.
- 쓸데없는 장식 문구는 넣지 않는다.

## 완료 기준
- 보고서만 읽어도 작업 내용을 이해할 수 있다.
- 실제 확인한 사실과 추측이 섞이지 않는다.
