# Report Write Skill

작업이 끝난 뒤 보고서를 쓸 때 쓴다.

## 언제 쓰는가
- 큰 기능을 넣었을 때
- API/DB/서버 구조를 바꿨을 때
- GitHub 운영 규칙을 수정했을 때

## 입력으로 필요한 것
- 변경한 파일 목록
- 수정된 다이어그램
- 검증 결과
- 남은 문제
- 다음 단계

## 작성 순서
1. 다이어그램을 맨 위에 둔다.
2. 요약을 먼저 쓴다.
3. 변경 내용을 짧게 정리한다.
4. 검증 결과를 적는다.
5. 남은 이슈를 적는다.
6. 다음 단계로 끝낸다.

## 완료 기준
- 한국어로 작성됐다.
- 수정된 다이어그램이 최상단에 있다.
- 무엇이 바뀌었는지 바로 보인다.
- 검증 결과가 있다.
- 다음 행동이 있다.

## 저장 위치
- 보고서는 `report/` 아래에 둔다.
